# Поиск, продавцы и поддержка — обновление Juz Market

## Установка

1. Остановите запущенный сервер продавцов.
2. Из архива `Juz-Market-changes.zip` скопируйте содержимое папки `Juz Market` в свою существующую папку проекта, согласившись на замену совпадающих файлов. Это дополнение, а не отдельный проект: старую папку целиком удалять не нужно.
3. В папке проекта запустите `npm run sellers` и в другом терминале `npm run dev`.
4. Ваши существующие серверы товаров `juz-market-api` (4000) и входа `juz-market-auth` (4001) также должны работать, как раньше.

Новые зависимости не добавлены. `package.json` и `package-lock.json` сохранены. Архив изменений не содержит `node_modules`, базы данных, ключа администратора или фотографий паспортов. Существующая папка `seller-server/data` остаётся на месте: новые поля для поддержки и блокировок добавятся автоматически при использовании.

## Поиск

Нажатие поиска в шапке или нижнем мобильном меню открывает каталог. Введите запрос и нажмите «Найти» или Enter. Учитываются название, категория, описание, магазин и характеристики товара. Регистр и буква ё не влияют на результат; небольшие опечатки и перестановка соседних букв допускаются. Например, «телефно» найдёт «Телефон». Точные совпадения идут первыми. Поиск работает вместе с фильтром категории; запрос сохраняется в адресе страницы. «Сбросить» убирает запрос.

## Продавцы

Откройте `/admin/users` → «Аккаунты продавцов». Введите тот же ключ администратора, который используется в разделе заявок: `seller-server/data/admin-key.txt` (либо значение `SELLER_ADMIN_KEY`).

Показаны магазин, ФИО, почта, телефон, число товаров и статус. Пароли не раскрываются: существующая система хранит хеши, из которых нельзя получить исходный пароль. Кнопка «Открыть кабинет» открывает кабинет продавца в режиме администратора: можно просмотреть товары, описания, характеристики и удалить товар без входа по паролю продавца.

Блокировка отзывает действующие сессии продавца, запрещает вход и изменения товаров, скрывает его товары из публичного каталога и страниц товара. Администратор сохраняет доступ к просмотру и удалению товаров. Разблокировка возвращает оставшиеся товары в каталог; продавцу нужно войти заново. Удалённые товары автоматически не восстанавливаются. Действия сохраняются в `moderationLog` базы продавцов.

## Чат поддержки

Пользователь: `/profile` → «Чат поддержки». При первом открытии переписки в текущей вкладке нужно подтвердить пароль своего аккаунта покупателя. Сервер поддержки проверяет логин и пароль через существующий `juz-market-auth`, не сохраняет пароль и выдаёт отдельный токен переписки. После выхода из профиля доступ к переписке в этой вкладке закрывается; сама история сохраняется.

Администратор: `/admin/support` → ключ администратора → обращение → ответ. Сообщения обновляются примерно каждые 4 секунды, показан счётчик непрочитанных обращений. История хранится на сервере в `seller-server/data/market.json`, доступна с разных устройств после входа и сохраняется после перезапуска. Повторная отправка того же запроса при сетевой ошибке не создаёт дубликаты. Максимальная длина сообщения — 2000 символов.

## Если сайт работает на домене

Новый функционал использует существующую настройку `VITE_SELLER_API_ORIGIN` — доступный браузерам HTTPS-адрес сервера продавцов. Укажите домен сайта в `SELLER_ALLOWED_ORIGINS` сервера (через запятую). Для связи сервера поддержки с сервером входа можно задать `SUPPORT_AUTH_API_ORIGIN`, по умолчанию `http://localhost:4001`. После изменения переменных Vite нужна новая сборка, после серверных — перезапуск сервера продавцов. Адрес `localhost` в браузере другого человека указывает на его компьютер, поэтому для общего сайта необходим адрес вашего сервера.

Сервер поддержки использует уже применяемый сайтом контракт: `POST /api/auth/login` с `{ login, password }`, ответ `{ token, user }`, где `user.id` — стабильный идентификатор; техническую сессию закрывает через `POST /api/auth/logout` с Bearer-токеном. Самого проекта `juz-market-auth` в исходном архиве нет: интеграция проверена с тестовым сервисом, повторяющим этот контракт.

## Проверка

Проверены production-сборка, lint новых компонентов, серверные сценарии поиска/блокировки/чата, сохранение переписки после перезапуска и изоляция пользователей. В браузере проверены поиск и навигация, отправка сообщения и ответ администратора, автоматическое обновление, контакты продавца, блокировка, удаление товара и разблокировка, а также мобильные кнопки поиска и профиля. Проверки выполнялись на отдельной тестовой базе; исходные аккаунты, ключи и паспортные фотографии не менялись.
