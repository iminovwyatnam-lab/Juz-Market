# Сохранение входа и данных

## Установка

Остановите старый `npm run dev`. Из этого архива перенесите в существующий проект только:

- `package.json`
- `vite.config.js`
- `src/seller/sellerApi.js`
- `scripts/run-with-sellers.mjs`

Запустите `npm run dev`. Он теперь запускает сайт и сервер баннеров/продавцов вместе. Если `npm run sellers` уже работает, используется существующий сервер. `npm run preview` тоже запускает сервер данных.

Папку `seller-server/data` в работающем проекте не удаляйте и не заменяйте: в ней актуальные продавцы, заявки, баннеры, товары и фотографии. В полном архиве эта папка оставлена ровно в состоянии присланного файла. Новые зависимости не добавлены.

## Что исправлено

- Вход продавца сохраняется в `localStorage` после закрытия вкладки и браузера. Старый открытый сеанс переносится автоматически при открытии кабинета. Если вкладка со старым сеансом уже закрыта, один раз войдите заново.
- Кнопка «Выйти» по-прежнему завершает сеанс, но не удаляет продавца, товары или баннеры. Срок серверного сеанса остался прежним — 7 дней; после него нужно войти снова, аккаунт сохраняется.
- При обычном локальном запуске сайт больше не запускается без сервера баннеров и продавцов.
- Vite больше не переходит молча с занятого порта 5173 на другой. Иначе браузер использовал бы другое хранилище и сохранённый вход покупателя, корзина и настройки выглядели бы потерянными. При занятом порте остановите старый процесс. Открывайте тот же адрес: `http://localhost:5173`. `localhost` и `127.0.0.1`, разные порты и разные браузеры имеют отдельное хранилище.

## Что требуется для завершения исправления покупателей

В этом архиве нет сервера `juz-market-auth` (порт 4001), на котором создаются обычные пользовательские аккаунты. Сайт уже сохраняет их текущий сеанс в `localStorage`, но сохранение самих аккаунтов и серверных токенов находится в отсутствующем проекте. Эта часть не исправлена: нужен код `juz-market-auth` без `node_modules`, секретных `.env` и персональных данных. Для проверки сохранения старых товаров и категорий также нужен код отдельного `juz-market-api` (порт 4000).

Эти два сервера пока запускаются как раньше. Их нельзя заменить пустой новой базой без потери доступа к существующим аккаунтам и данным.

Если проблема возникает на опубликованном домене, сервер данных должен постоянно работать и использовать постоянный диск (`SELLER_DATA_DIR`), а сайт — его публичный адрес `VITE_SELLER_API_ORIGIN`. Локальный запуск не настраивает удалённый хостинг; размещение только фронтенда не запускает Node-сервер.

## Проверка

На отдельной тестовой базе проверены: регистрация и одобрение продавца, вход, перенос старого сеанса, сохранение Web Storage между отдельными процессами клиента, перезапуск сервера, выход и повторный вход, сохранение товаров, трёх баннеров и точных байтов изображения. Проверены совместный запуск/остановка процессов и использование уже работающего сервера. Проверки синтаксиса и ESLint изменённых файлов пройдены.

Полную сборку Vite в проверочном Linux-окружении выполнить не удалось: в присланном `node_modules` есть только Windows-версия нативной зависимости Rolldown. Зависимости и lock-файл не менялись. Проверка браузером также недоступна в этом окружении; проверка клиентского сохранения выполнена через Web Storage Node.js. Дизайн, разметка и существующие данные не изменялись.
