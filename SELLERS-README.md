# Раздел продавцов

## Запуск

В корне проекта откройте два терминала:

```bash
npm run sellers
```

```bash
npm run dev
```

Если зависимости ещё не установлены, сначала выполните `npm install`. Используйте версию Node.js, поддерживаемую текущим Vite проекта (22.12+ или 24+). Сервер продавцов использует только встроенные модули Node.js и не требует дополнительных пакетов.

Откройте `/seller`, например `http://localhost:5173/seller`. Вход также доступен через «Продавать на Juz Market» внизу сайта и «Кабинет продавца» в профиле.

## Работа продавца

1. Зарегистрируйте магазин: название, телефон, почта и пароль. Это отдельный аккаунт продавца; существующий вход покупателей не менялся.
2. Нажмите «Добавить товар»: фото JPG/PNG/WebP до 2 МБ, название, категория, описание, цена и остаток.
3. Опубликованный товар появляется в общем каталоге и открывается по отдельной ссылке. Работают существующие корзина, избранное и оформление заказа.
4. В кабинете можно изменить или удалить только собственные товары. Название магазина и телефон отображаются в карточке товара и передаются в состав заказа для администратора.

Товары, аккаунты и фотографии сохраняются на сервере в `seller-server/data/`, а не в браузере продавца. Не удаляйте эту папку; делайте её резервную копию. Пароли сохраняются в виде солёных хешей. Сессия продавца действует до 7 дней, хранится в текущей вкладке и отзывается при выходе. Остаток редактируется продавцом вручную: автоматическое списание и резервирование не добавлялись.

## Админка

В `/admin/products` убрано добавление товаров. Прежние товары можно редактировать как раньше; товары отдельных магазинов отображаются с именем продавца и управляются через его кабинет.

В `/admin/orders` откройте заказ и выберите «Отменён». Появится кнопка удаления в строке и в окне заказа. После подтверждения заказ действительно удаляется из сохранённого списка, включая историю покупателя. Активные и доставленные заказы эта функция не удаляет.

## Существующие серверы проекта

В исходном архиве нет кода серверов `juz-market-api` (порт 4000) и `juz-market-auth` (порт 4001). Для прежних товаров и входа покупателей запускайте их как раньше. Новый сервер на порту 4002 работает отдельно. Если один сервер товаров недоступен, каталог может показать товары доступного сервера.

Существующее оформление заказов по-прежнему использует `localStorage` (`jm_orders`): такие заказы видны только в том браузере, где оформлены. Обмен заказами между устройствами, поступление заказов в кабинет продавца и онлайн-оплата не добавлялись. Для реального приёма заказов покупателей с разных устройств необходим общий сервер заказов; в исходном проекте его нет.

## Подключение к домену

Для локального запуска настроек не требуется. Для своего сервера:

- `SELLER_PORT` — порт, по умолчанию `4002`.
- `SELLER_HOST` — адрес прослушивания, по умолчанию `127.0.0.1`.
- `SELLER_DATA_DIR` — при необходимости другой постоянный каталог данных.
- `SELLER_ALLOWED_ORIGINS` — разрешённые адреса сайта через запятую, например `https://your-shop.example`. Для разработки по умолчанию разрешены localhost и 127.0.0.1 на портах 5173 и 4173.
- `VITE_SELLER_API_ORIGIN` — публичный HTTPS-адрес сервера продавцов, без `/api`, например `https://seller-api.your-shop.example`. Добавьте его в `.env.local` перед сборкой сайта.

Запустите `npm run sellers` как постоянный процесс за HTTPS-прокси и укажите публичный адрес API перед `npm run build`. Для доступа с другого устройства адрес localhost не подходит.


## Заявки продавцов

Регистрация продавца теперь отправляет заявку: фамилия, имя, отчество, название магазина, телефон, почта, паспорт, дата рождения, пароль и фото паспорта с двух сторон. Кабинет открывается только после одобрения.

В админке открыт раздел `/admin/applications` («Заявки»): список заявок, окно «Рассмотреть» со всеми введёнными данными и фото паспорта, кнопки «Одобрить» и «Отказать». После отказа продавец может отправить новую заявку с той же почтой.

Раздел защищён ключом администратора, потому что в нём паспортные данные. Ключ создаётся при первом запуске `npm run sellers`, лежит в `seller-server/data/admin-key.txt` и печатается в консоли. Его можно задать самому через переменную `SELLER_ADMIN_KEY`. Фото паспортов лежат в `seller-server/data/passports/` и отдаются только по ключу. Не публикуйте папку `data` и делайте её резервную копию.
